## 1. The "Ghost in the Machine" (Runtime Behavior)
*Note to Opus: Since you cannot run the code, these are the critical runtime behaviors I observed in the browser that are NOT obvious from the static source.*

### A. The Authentication "Deadlock"
- **Incident**: After updating `JWT_SECRET` in `.env`, the frontend entered a loop of `403 Forbidden` errors.
- **Cause**: The frontend (using `zustand/persist`) stores the old JWT in `localStorage`. The backend rejects it, but the frontend doesn't automatically clear it on 403, leading to an infinite retry loop.
- **Context for Fix**: A global axios interceptor or a more robust `useAuth` hook is needed to clear `localStorage` on 401/403 errors.

### B. The Data Discrepancy (Real vs. Fake)
- **Observation**: I observed a 30% price discrepancy between the **Dashboard** and the **Markets** page.
- **Dashboard**: Shows real prices (e.g., AAPL $285.24) fetched from the backend poller.
- **Markets Page**: Shows fake prices (e.g., AAPL $178.42) generated by a random math function in the React component.
- **Confusion**: This creates a "broken" feel where the user doesn't know which data to trust.

## 3. The Intelligence Chain Collapse (DAG Audit)

The **Agentic DAG** (Fetch -> News -> Forecast -> Risk -> Alert) is the heart of the app. In Phase 2, it has collapsed:

1.  **News Node Failure**: This node turns **RED** during execution. 
    - *Suspected Reason*: The `genai` library initialization in `GeminiClient` or a schema mismatch when saving `NewsItem` to the DB (e.g., trying to save a 501-character headline to a `String(500)` column).
2.  **Cascading Failure**: Since `Risk` and `Alert` synthesis depend on the `news` list in the `AgentState`, they fail to generate a valid response.
3.  **CitationGuard Redaction**: Even if the AI generates a "general" guess, the **CitationGuard** (our anti-hallucination layer) redacts it because there are no supporting "news" citations in the state.

## 4. The "Missing 10%" (Production Hardening)

To move beyond an MVP and into a 100% production-ready state, the following architectural gaps must be closed:

### A. Server-Side Data Consolidation
- **The Problem**: 1,000 users = 1,000 independent requests to `yfinance` every 15s. This will trigger an immediate IP ban.
- **The Solution**: The backend `poll_loop` should act as the "Single Source of Truth." It updates a redis/local cache, and the WebSocket Hub broadcasts *that* cache to all users.

### B. Portfolio History Tracking
- **The Problem**: We have a "Holdings" snapshot, but no "Portfolio Performance" chart.
- **The Requirement**: A background worker needs to snapshot the total portfolio value (Sum of `quantity * live_price`) daily to populate a historical chart.

### C. Settings Persistence & UI Placeholders
- **The Problem**: The Settings UI is a hollow shell. It currently displays a **"Coming Soon"** message across all tabs (General, Security, API).
- **The Requirement**: Toggles for "Strict Citation Mode," "API Usage Tiers," and "Alert Preferences" must be added to the `User` model and persisted via a `/users/settings` endpoint.

### D. Error Boundaries & Graceful Degradation
- **The Problem**: If the News API fails, the user sees a "Red X" and a broken app.
- **The Requirement**: The DAG should be "fault-tolerant." If the News node fails, the Alert node should still produce a response with a disclaimer: *"Analysis based on market data only; live news feed currently unavailable."*
