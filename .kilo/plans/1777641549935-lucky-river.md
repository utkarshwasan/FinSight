# Fix Plan for FinSight AI Issues

## Current Status Summary
The application is running but has several issues preventing login and proper functionality:

1. ✅ CandleChart.tsx import fix APPLIED (separate type/value imports)
2. ❌ CORS issue - backend has allow_origins=["*"] but login returns 500 error
3. ❌ Database seeding failing - psycopg event loop issue on Windows
4. ❌ No demo user in database - login fails with "Invalid credentials"

## Root Cause Analysis

### Issue 1: Lightweight Charts Import - FIXED
The import in CandleChart.tsx has been fixed by separating type imports from value imports. The types (IChartApi, ISeriesApi, Time, CandlestickData, LineData) are imported as type-only, and the values (createChart, ColorType, CandlestickSeries, LineSeries, LineStyle) are imported separately.

### Issue 2: Database Seeding Failure  
The seed script in `backend/app/scripts/seed_demo.py` fails with psycopg event loop error on Windows. The script needs a SelectorEventLoop policy but sys wasn't imported at module level initially (now fixed).

**Key Problem**: DATABASE_URL in seed_demo.py doesn't convert to async URL properly when run standalone. It uses `"postgresql+psycopg://..."` but needs `"postgresql+psycopg_async://..."` for async operations.

### Issue 3: No Demo User in Database
Because seeding fails, the `demo@finsight.ai` user doesn't exist in the database, causing login to fail with "Incorrect email or password" (500 error after the auth check raises an exception).

### Issue 4: DATABASE_URL Configuration Mismatch
The seed script and quote_poller both construct their own DATABASE_URL, which may not match the application's URL format. The main app uses:
```python
_DATABASE_URL = os.getenv("DATABASE_URL", "postgresql+psycopg://postgres:postgres@localhost:5432/finsight")
ASYNC_DATABASE_URL = ...  # Converts to async
```

But seed_demo.py uses:
```python
DATABASE_URL = os.getenv("DATABASE_URL", "postgresql+psycopg://postgres:postgres@localhost:5432/finsight").replace("postgresql+psycopg://", "postgresql+psycopg_async://")
```

This should work, but psycopg3 needs the async driver for async operations.

## Immediate Fixes Required

Since Docker Compose is configured with DEMO_MODE=1, we could:

2. Run seed script inside the backend container
3. This avoids Windows event loop issues

### Fix 3: Direct Database Insert (Fallback)
If psycopg async continues to fail, we can insert demo data directly via psql or sync SQLAlchemy.

## Technical Details

### psycopg3 Async Issue
psycopg3 requires `postgresql+psycopg_async://` driver for async operations. The seed script converts the URL but may still have issues with ProactorEventLoop on Windows.

### DATABASE_URL in docker-compose
```yaml
environment:
  - DATABASE_URL=postgresql+psycopg://postgres:postgres@db:5432/finsight
```

This is used by the backend app which converts it to async. The seed script needs the same treatment.

### DEMO_MODE Behavior
With DEMO_MODE=1 (set in docker-compose):
- GeminiClient uses fixture data
- YFinanceClient uses fixture data
